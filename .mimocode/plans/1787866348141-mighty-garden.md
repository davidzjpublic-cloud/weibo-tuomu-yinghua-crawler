# 龙虾项目重构计划

## 目标
清理死代码、消除重复、整理目录结构，提升可维护性。不改变功能行为。

## 重构项（按优先级排序）

### 1. 删除 lobster.py（964 行死代码）
- **原因**：旧版单文件，已被 main.py + crawler.py + extractor.py + models.py + quark.py + douban.py + utils.py 完全替代，零引用，内含 bare `except` 等代码坏味道
- **操作**：直接删除 `lobster.py`

### 2. 提取 CDP 共享代码 → `cdp_utils.py`
- **原因**：`extract_quark_cookie_cdp.py`（338行）和 `extract_weibo_cookie_cdp.py`（392行）共享约 200 行几乎一模一样的基础设施代码
- **共享函数**：`get_requests_session()`, `find_chrome_exe()`, `hide_chrome_window()`, `launch_chrome()`, `wait_for_cdp()`, `get_page_ws_url()`, `get_all_cookies()`, `build_cookie_string()`, `write_config()`
- **操作**：
  - 新建 `cdp_utils.py`，放入上述共享函数（参数化 profile_dir/port/config_key/target_url）
  - 两个 CDP 脚本改为薄包装，各保留 ~50 行（目标站点配置 + cookie 特定逻辑 + main）
  - 同步检查 `extract_quark_cookie.py`（非 CDP 版）是否还有存在必要，如无则一并清理

### 3. 整理根目录输出文件
- **原因**：根目录堆积了 52 个 `filenames_*.txt` + 18 个 `results_*.json` + 各种 `.log`，共 70+ 个生成产物
- **操作**：
  - `.gitignore` 新增：`filenames_*.txt`, `results_*.json`, `*.log`, `lobster.log`, `chrome_weibo_cdp_debug.log`, `chrome_*_profile/`, `.douban_cache.json`, `processed_weibo.json`, `result*.txt`
  - 将现有的 `filenames_*.txt` 和 `results_*.json` 移入 `output/` 目录（`main.py` 输出路径相应改为 `output/`）
  - 更新 `备忘.txt` 和 `需求.txt` 中引用的文件路径
  - `test_regenerate.py` 和 `build_douban_cache.py` 中硬编码的文件路径一并更新

### 4. 清理根目录散落的临时测试脚本
- **原因**：根目录有 13 个一次性调试脚本（`test_control.py`, `test_war.py`, `test_subtitle.py`, `test_language.py`, `test_language_debug.py`, `test_douban_api.py`, `test_douban_mobile.py`, `test_douban_movie.py`, `test_text_repr.py`, `test_lang_part.py`, `test_regenerate.py`, `test_control_debug.py`, `test_control_debug2.py`），用 `sys.path.insert` hack，不是正规 pytest
- **操作**：
  - 有回归价值的（如 `test_regenerate.py`）移入 `tests/` 并改写为正规 pytest
  - 纯一次性调试脚本直接删除
  - `compare_filenames.py` 和 `build_douban_cache.py` 保留（是工具脚本而非测试），但移入 `tools/` 或保留原位

### 5. 修复 models.py 的代码坏味道
- **`_build_role_parts()` 中 `invalid_keywords` 作用域脆弱**（models.py:134→157）：director 块里定义的局部变量被 supervisor 块复用，删掉 director 块会导致 supervisor 报错。改为复用 `config.py` 中已有的 `INVALID_DIRECTOR_KEYWORDS`
- **重复的 keyword 列表**（models.py:134-138 vs 166-170）：director/writer 用了各自的内联列表，应统一使用 `config.py` 的常量

### 6. 补充 utils.py 直接单元测试
- **原因**：`safe_filename()` 和 `clean_html()` 目前无直接测试，仅被间接调用覆盖
- **操作**：在 `tests/test_utils.py` 中添加针对这两个函数的用例

### 7. 精简运行日志
- **原因**：当前日志过于冗长，淹没了关键信息。用户反馈"运行过程中给出的信息太多了"
- **原则**：保留关键步骤进度和分步结果，中间细节降为 DEBUG
- **crawler.py 需降级为 DEBUG 的**：
  - 每次请求前的等待日志（`等待 X 秒后请求...`）
  - 原始响应预览（`原始响应: ...`）
  - 单条微博摘要（`微博 0: ID=..., 内容=...`）— 保留汇总数即可
  - XSRF-TOKEN / Cookie 长度等初始化细节
  - 接口尝试日志（`尝试接口: ...`）
- **main.py 需降级为 DEBUG 的**：
  - 每条评论的详细解析（`评论 0: ... 结构化链接: ... 短链: ...`）
  - 非目标日期微博（`非目标日期发布`）— 太频繁，翻页时大量出现
  - 非影视内容跳过（`跳过非影视内容`）
  - 图片上传重试细节
- **main.py 保留 INFO 的**（关键步骤 + 结果）：
  - 启动参数、目标日期
  - 每页微博获取（`获取第 N 页微博...`）
  - 每条影视微博处理（`处理微博 [id]: 书名...`）
  - 夸克链接发现（从正文/评论找到）
  - 文件名生成结果（`✅ 提取成功 N: 名称`）
  - 转存结果
  - 最终汇总（条数、耗时）
- **操作**：逐文件将上述 `logging.info()` 改为 `logging.debug()`，关键行保持 `logging.info()`

## 不动的部分
- 核心提取逻辑（extractor.py）—— 测试覆盖优秀（60+ 测试），改规则是日常迭代的事，不属于本次重构
- douban.py / quark.py / crawler.py 的功能逻辑 —— 只做目录整理，不改行为
- 需求.txt / 备忘.txt 的内容 —— 只更新路径引用

## 执行顺序
1 → 2 → 3 → 4 → 5 → 6 → 7（每步完成后跑 `pytest tests/ -q` 确认无回归）

## 验证
- 每步完成后：`pytest tests/ -q` 全绿
- 最终：`python main.py --help` 正常输出；`python main.py --target-date 2026-08-18 --limit 1` 不报错（如果需要实测）
- git diff 确认无功能行为变化
